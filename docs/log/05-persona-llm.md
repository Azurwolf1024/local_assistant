## 57. 角色素材导入：台词清单 + 档案（★不看模板、批量、界面也能做★）（2026-10-11）

用户的请求（两件事一起说的）：

> 新角色克莱门莎（clementia），准备导入；同时我发现游戏设定的干员档案（角色档案）导入应该有助于塑造角色，
> 档案以 `profile.txt` 存在角色文件夹中，同样想办法做批量化导入，注意以后角色**可能不是同一个游戏，
> 不一定有固定模板**，做好适配。

「导入一个新角色」在这之前是**手工活**：`scripts/import_lines.py` 只能一次导一份台词清单（还得手写
`--json` 路径），档案/角色卡完全没入口 —— 人得自己读一遍档案，把人设要点抄进 `background`。
这一节把它做成了「放好文件 → 一条命令（或界面点两下）」。

### 57.1 先定方向：档案该进**知识库**，不是进提示词

这是本节最重要的一个决定，先说清楚为什么：

| 去处 | 什么时候进提示词 | 代价 |
| --- | --- | --- |
| 台词清单 → 人格文件的 `lines` | **每一轮都在** | 提示词变长（首字稍慢），但语气最稳 |
| 档案 → `data/knowledge/<id>/档案.md` | **检索命中才进** | 首字不变；问到相关设定时才捞出来 |
| 档案 → `background`（整段塞进去） | 每一轮都在 | 克莱门莎那份 15 KB，直接塞会稀释人设、还拖慢首字 |

所以：**台词进 `lines`，档案进知识库**。两条都是「已有机制」，没有新发明 ——
知识库那套（第 15 节）本来就是「按需检索的背景知识」，正好接档案。
实测（57.8）：档案 17 节进知识库后，问「阿戈尔」能命中 3 段，而**凯尔希查同一个词命中 0 段**（隔离正常）。

### 57.2 「不看模板」是怎么做到的：四条结构规则

做之前先看了手头的素材（`clementia/profile.txt`，明日方舟的干员档案）：
`基础档案` / `综合体检测试` / `客观履历` / `临床诊断分析` / `档案资料一~四`，
里面混着 `【代号】克莱门莎` 这样的键值、`提升信赖至 50% 以查看` 这样的**解锁门槛行**、
`【一份投诉信，来自克莱门莎的医师】` 这样的引文小标题，还有大段剧本体对话。

★如果按这份模板写解析，换个游戏就废★。所以 `parse_profile()` 只认**结构**：

1. **短行 + 后面还有正文** = 章节标题（`## 档案资料一`、`一、基础档案`、`【一份投诉信】` 都算；
   带 markdown 标记的不限长度，英文标题比中文长）；
2. **`【键】值` / `键：值` 出现在一节开头**（还没写正文时）= 这一节的元信息表；
   一旦这节开始写正文，后面的方括号行**原样留在正文里**（「临床诊断分析」把两个数值夹在句子中间的排版不会被拆散）；
3. **门槛行**按通用形状丢掉（`…以查看/解锁`、`初始开放`、`精英化1解锁`、`locked/unlocked…`），
   `--keep-gates` 可以留着；
4. 其余是正文，**按空行分段原样保留**（剧本体一行一句的排版不动它）。

另外两条「不吃亏」的细节：引文行（`【…】` 单独一行）**自己成一节**（它的标题信息量比「档案资料一」大）；
以 `“`/`「` 开头的行**不当标题**（否则一段访谈会被拆成一问一答两节，检索命中「问」时拿不到「答」）。

自测拿**两套完全不同的模板**各走一遍（中文方括号 + 门禁行；英文 Markdown + `- key: value`），
外加一份**纯散文**（整篇当一个章节）。

### 57.3 ★识别素材：四个判据★（这一步比解析更容易出错）

一个角色文件夹里会有多种 txt，必须自己判断谁是谁：

| 情况 | 判据 | 结论 |
| --- | --- | --- |
| `ref_join_B.txt` 配 `ref_join_B.wav` | 文件名和目录里的音频同名 | **ignore**：那是那段音频的**逐字文本**，不是给知识库的素材 |
| `clementia.txt` + 38 个音频 | 多数条目名对得上音频名 | **lines**（压倒性证据） |
| 目录里还没有音频，文件叫 `<目录名>.txt` | 命名约定 | **lines** |
| 目录里没有音频，整篇是「短标签 + 一段正文」 | 形状 | **lines** |
| 其余 | 章节数 / 元信息数 / 长度 | **profile**，都不够就 **ignore** |

★两条判据都是被实际误判逼出来的★（都发生在沙盒/自测里，不是想象出来的）：

- 「至少 3 条名字对上音频」这个门槛把**只有两条台词的小清单**判成了档案 → 改成「多数对上」；
- 沙盒目录里**没有音频**时，`probe.txt`（3 条台词）被判成档案 →
  加了「和目录同名」与「短标签 + 一段正文」两条判据。

### 57.4 顺带修掉一个真 bug：`profile.txt` 会污染台词清单

`voice_loop/manifest.py` 的 `manifest_pairs(directory)` 会把角色目录下**所有** `*.txt`
当台词清单读 —— 而 `profile.txt` 就住在同一个目录里，它的排版（短行标题 + 大段正文）
和清单**一模一样**。后果分两级：

- 平时只是噪声（档案的小标题进了清单表）；
- **一旦某个标题和音频同名**（比如档案里真出现「问候」「交谈1」这种小节名），
  零样本克隆就会拿**错的文本**当参考文本 —— 而参考文本与音频不一致会**明显掉音色**
  （README 第 14 节专门写过这条）。

修法：`is_manifest_file()` 排除 `profile*` / `档案*` / `README` / `_` 开头的文件，
`manifest_pairs` 用它；自测盯着「真实 kaltsit 目录里 `ref_*` 不再出现」。

### 57.5 两个自己踩的坑（各有一条回归测试）

1. ★**算完合并没写回 `data`**★：第一版 `import_char()` 把新增台词算进 `added_lines`、
   报告里写着「台词 +38」，**但从来没写进那个 dict**，文件里仍是 0 条。
   我是导完克莱门莎、去数 `Character.lines` 时发现 `lines= 0` 才抓到的 ——
   报告与文件不一致是最难发现的一类 bug。回归：自测直接读回 json 数 `len(lines)`。
2. ★**正文缓冲区跨章节没结算（串味）**★：`pending` 里的正文只在「遇到引用行」和「文件结束」时
   并入当前节，于是**第一节的字全跑到最后一节**去了（17 节的档案只剩 2 节，最后一节 4772 字）。
   修法：切节/换标题前先结算，并把「这节还是空的吗」的判断**算上 `pending`**
   （不算它就会把「上一节正文还没结算」误当成空节，于是标题被覆盖、正文跟进下一节）。

### 57.6 三条不变量（跟 `import_lines.py` 同源）

1. **只添加，不替换**：人格文件里已有的内容一个字都不动（去重按「抹掉空白后的正文」比，所以
   `你好呀` 与 `你好 呀` 算同一条）；
2. **默认试运行**：`--apply` 才写盘，写前 `.bak`（人格文件、索引、被覆盖的知识库文件各一份）；
3. **幂等**：同一份素材导两次，第二次报告必须是「+0 条 / 档案内容没变」。

另外两个开关：`--world 明日方舟` 把档案放进 `data/knowledge/_worlds/明日方舟/`
（同 IP 的角色共享，并往人格文件的 `worlds` **追加**那个名字，只加不减）；
`--create --add-index` 给「还没有人格文件」的角色生成**能跑的骨架**
（名字/身份/背景/台词/世界观从素材里尽量填，风格那几栏留给人补）——
骨架默认**不进索引**：不进索引就不会被唤醒，人补完再上线。

### 57.10 诚实清单

- **同名音频的 txt 一律忽略**：这是「那段音频的逐字文本」的约定。真有一份素材叫 `标题.txt`
  而目录里又有 `标题.wav`，它会被跳过 —— 用 `--as lines/profile` 可以强制（自测覆盖了这条）。
- **纯散文只能靠长度判断**（≥120 字算档案）：太短的手写角色卡会被判成「不是素材」，
  给 `--as profile` 就进来了。
- **档案不进提示词**：所以「一上来就自我介绍」这类问题要靠**检索命中**才拿得到设定里的细节；
  想让它无条件知道，就把要点写进 `background`（这也正是 `background` 的用途）。
- **不是同一游戏也能进，但提取质量取决于排版**：完全没有分隔（一整段 5000 字）的档案会变成
  一个大章节，检索粒度会变粗（知识库按 900 字硬切）。
- **`--create` 出来的骨架只是「能跑」**：`background` 用的是档案第一段（第三人称），
  报告里会提醒改写成第一人称；风格那几栏本来就该人写。
- 全量跑时 `test_store_lock` 偶发失败一次（`条数对得上`），单独重跑即过 ——
  和 §56.9 记的 `test_offline` 同一类 Windows 文件/时序竞态，与本节无关。

## 58. 人设「出戏」与幻觉：提示词从「文档」改成「人设卡」（2026-10-12）

用户的请求（原话）：

> 我感觉身份卡有问题，和助手聊天时经常出现幻觉，有时会强行扯到身份卡上的提示词，
> 比如白天莫名其妙说「你又熬夜了」，这很出戏；想办法检查并解决，让模型幻觉减少，更像正常人。

这句话里其实有三个独立症状，§58 就是按这三个症状分别归因、分别修的：

1. **凭空的关心**：白天（对话发生在下午）说「你又熬夜了」；
2. **扯身份卡**：回答里冒出提示词/设定的内容（「按您的设定……」「您提到的『睡没睡』」）；
3. **幻觉**：编日程、编身份、编记忆。

### 58.1 先量，再改：三条真归因 + 一条被证伪的假设

| 怀疑 | 怎么量的 | 结论 |
| --- | --- | --- |
| 提示词里的**示例句**被照搬 | 逐条读 `data/personas/*.json`，找出「比如「完整一句话」」这种写法 | ★真凶之一★：`kaltsit.style[3]`、`clementia.style[5]` 里写着「你又熬夜了」整句，4B 会原样搬到不相干的回合 |
| 台词太多把 `num_ctx` 撑爆 | `prompt_eval_count` 实测五个角色 | 白泽 688 / 凯尔希 1604 / 阿米娅 1403 / 能天使 488 / 克莱门莎 **2232** tokens（`num_ctx` 4096），溢出时 Ollama 从头截断 → 人设整段丢失 |
| 模型「没有时钟」所以在猜白天黑夜 | 给 `/api/chat` 加一行「现在是……15:00」再问 | 有了时间就不再主动提作息；没有就照人设里的示例句编 |
| **改 Ollama 模版**能让模型「认真扮演」 | `POST /api/create` 造一个带 ChatML 模版的新模型，再对比三个模型的回答 | ★假设被证伪★：Ollama 0.40 的 `RENDERER qwen3.5` 会忽略存储的 `TEMPLATE`，新模版**完全不生效**（三个模型回答一字不差） |

被证伪的那条尤其值得记：我一度写了 `scripts/fix_model_template.py`（`ollama show` 显示模版只有
一行 `{{ .Prompt }}`，看起来像「没套对话模版」），但它**当场被实验否掉**，所以**删掉了** ——
留着它等于留一个「看起来能修、实际什么都不做」的按钮。想改模版这件事，Ollama 0.40 上做不到。

### 58.2 ★真正的病灶：提示词写成了一份「文档」★

把同一份人设喂给 `qwen3.5:4b`（`think=off`，语音必须关思考，否则 +10 s），行为是这样的：

| 提示词形态 | tokens | 结果 |
| --- | --- | --- |
| 原样（`★` / `**` / 编号 / `【】` 分节 / 38 条台词） | 1737 | **拒绝扮演**：「作为一个人工智能助手……不能进行角色扮演」；或退化成「我不知晓您的身份」 |
| 同样的文字，只去掉装饰符号 | 1651 | 不拒绝了，但有回答**把提示词原样复述**出来（「……【只说真话】这一节比下面的说话风格更重要……」） |
| 压成 150~250 字的口语人设卡 | 123~198 | 正常聊天 |

也就是说，问题不在「写得够不够详细」，而在**写得像不像一份文档**：
4B 见到分节的、带编号和星号的文本，第一反应是「这是一份要我处理/审阅的材料」，
于是它开始**交作业**（拆解要求、列要点、注解「已按用户要求生成」），而不是**说话**。

由此定下 compact 的五条禁忌（全部有回归测试兜着，见 `scripts/tests/test_persona.py` 第 [2b] 节）：

1. **短**：目标 200~300 字，硬上限 420（超了 lint 就报）。
2. **像人设卡，不像指令书**：只写陈述句（「你是阿米娅，罗德岛公开领袖，出自《明日方舟》，正和博士说话。」），
   不写「你要做到以下几点」「学那个语气」—— 这些**元指令**本身就是「有人在派任务」的信号。
3. **只说肯定句**：写「不要自称 AI」，它就回「我是白泽（AI 助手）」；写「不要用符号和列表」，
   它就点评「你给的文本里有符号」。★否定句会被照念★。
4. **不带引号和标签**：`【此刻】` 被念成「现在【此刻】是……」；「这个我不知道」被复述成
   「您刚才说的『这个我不知道』是指……」。所以时钟改成一句白话（`now_block`），人设里不出现引号。
5. **不写行为规则**：把「不清楚就说不知道」「日程先查再报」写进人设，实测凯尔希答过
   「我甚至知道博士的日程和备忘录」。这些规矩属于**每轮的运行时提示**（`TRUTH_HINT`），不属于人设。

另外两个小的但很实在的发现：

- **开头必须有「你」**。写成「凯尔希，罗德岛医疗主管……」，模型以为在介绍**别人**，
  会用第三人称谈她（实测：「关于您提到的那个凯尔希……她不在场」）。
- **风格条目只取第一个分句**。「偶尔可以提到罗德岛、简报、档案这些词，但不要硬塞」这种
  半句是**指令**，模型会把它当台词念出来（「你不需要硬塞，只要偶尔提一句……」）。

### 58.3 数据侧：把「会让它学坏」的素材挡在提示词外

渲染时多了一层过滤（`persona._plain` / `_LINE_SKIP` / `_tone_entries`），原则是
**改提示词，不改用户的数据**：

| 过滤 | 挡掉什么 | 为什么 |
| --- | --- | --- |
| `_plain` | `★` `☆` `**` `【】` `「」` | 装饰符号会被当成格式要求，回答里跟着冒星号方括号 |
| `_LINE_SKIP` | 战斗/剧情台词（接敌、阵型、战死……）+ **作息台词**（熬夜、没睡、早点睡） | 「您又熬夜了……我也没睡」正是用户抱怨那句的出处 |
| `_LINE_NOISE` | `(提升至精英阶段1以查看)` 这类图鉴噪音 | 念出来莫名其妙 |
| `_tone_entries` | 否定词多、第三人称、元词汇（这些词/称呼/结尾/硬塞）多的风格条目 | 见 58.2 第 3、5 条 |
| `_short_lines` | 太短（「可以。」）太长（独白）的台词 | 挑「一句话」，并按用户的原顺序输出（那是人物的语序） |

顺手清掉的数据问题：`baize` / `exusiai` 的 `rules` 里有 `★用第一人称说话，不要自我介绍★`
（这是渲染器早就统一处理的事，写在数据里只会被模型念出来），`clementia` 的 `style` 里有 `★`。

`scripts/lint_persona.py` 现在是这套规则的守门员，并**进了 `sessions\run_tests.cmd`**
（它不是单元测试，而是对**真实**人格文件做体检，有告警就 EXIT=1）：

| 检查项 | 会出什么事 |
| --- | --- |
| 可照抄示例 | 那句完整的话会被原样搬到别的回合 |
| 作息话题 | 模型把它当成「要主动关心」的话题清单 |
| 装饰符号 | 回答里开始出现 `**`、`【】` |
| 提示词长度 > 420 字 | 4B 开始把提示词当文档议论 |
| 台词重复 / 作品名两头不一致 | 白占预算 / 知识库不共享 |

改完之后实测的体积（同一批角色）：

| 角色 | 原来 | 现在 | 台词 |
| --- | --- | --- | --- |
| 白泽 | 688 | **136** | 5/5 |
| 凯尔希 | 1604 | **198** | 6/39 |
| 阿米娅 | 1403 | **165** | 6/39 |

### 58.4 运行时兜底：第一句出戏就换个人设重答

提示词再怎么改，4B 在 `temperature 0.7` 下同一份人设也时而像人、时而交作业 ——
所以「只靠提示词」是不可能 100% 的。真正兜住的是**开口之前看一眼**：

```
人设 system + 运行时 system（此刻 + 工具规则 + TRUTH_HINT）+ 用户
        ↓
第一遍：先把开头攒着（GUARD_MIN_CHARS=24 字）→ reply_problem() 判一次
        ├─ 没问题 → 照常放行（这 24 字补念，用户听不出差别）
        ├─ 可疑开头（{ / [ 工具 JSON）→ 交给原来那套「写成文字的工具调用」逻辑
        └─ 出戏（拒绝扮演 / 议论提示词 / 交作业排版 / 复述人设）
              → 整段丢掉（一个字都没念出去）→ 换极简人设（一句话）重答一次
```

`persona.reply_problem()` 的四类判据都是 §58 里**真的出现过**的回答：

| 判据 | 命中示例 |
| --- | --- |
| 拒绝扮演 | 「作为一个人工智能助手，我无法扮演……」 |
| 议论提示词 | 「您提供的这段文字似乎是一段经过加密、错乱或故意拼凑的文本」 |
| 交作业排版 | 开头就是 `**结论：**` / `| 时间 |` 这种表格化输出 |
| 复述人设 | 与人设原文有 20 字以上连续的 n-gram |

只在**第一遍**拦、只拦**开头**，是刻意的取舍：重试有成本（多一次生成 ≈ 2~4 s），
而这几类毛病全部在第一句就暴露；已经开始念了再改口，比容忍一次跑偏更伤。
`scripts/tests/test_persona_guard.py` 用假模型把这条分支跑通：第一次吐拒绝、第二次吐正常话，
断言「拒绝那句一个字都没念」「第二遍换上了极简人设」「最终回答是第二段」。

### 58.5 怎么验的

| 验的东西 | 怎么验的 | 结果 |
| --- | --- | --- |
| 提示词形态 | `scripts/tests/test_persona.py` 第 [2b] 节：开头有「你」、无装饰符号、无元指令、≤420 字、熬夜/战斗台词不进提示词、风格只取首分句 | 全过 |
| 出戏判据 | 同上第 [2c] 节：五个真实坏案例都拦得住，四个正常回答都放行 | 全过 |
| 兜底重答 | `scripts/tests/test_persona_guard.py`：假模型两段回答，断言只念第二段、第二遍换了极简人设 | 全过 |
| 真模型行为 | `sessions/probe_final.py`：五个角色 × 三问，固定 15:00（所以「又熬夜了」一定是编的），判「元话语 / 凭空关心 / 编造日程」 | 见下面的诚实清单 |
| 人格文件体检 | `scripts/lint_persona.py`：五个角色 | EXIT=0（干净） |
| 回归 | 全量 `sessions\run_tests.cmd`（**42 个脚本 + lint**） | 全 EXIT=0 |

### 58.6 诚实清单

- **4B 仍然会偶尔跑偏**。同一份人设跑 15 次，`probe_final` 这一轮还有 5 次被判异常
  （拒绝、议论提示词、编日程都有）。比改之前好很多（原先是**大多数**回答都在议论提示词），
  但这不是「彻底解决」，是「明显变好 + 有了兜底」。
- **兜底只看第一句**。跑到第三句才开始跑偏的，`reply_problem` 不管。
  真要在中途也管，就得把整段都攒着不念，首字延迟会毁掉语音体验 —— 没做。
- **`think=on` 能让它明显更稳，但不能用**：`num_predict 200` 时思考会把预算吃光、正文为空；
  而语音对话多等 10 s 不可接受。换大模型（20B+）时可以把 `[persona] prompt_style` 设成
  `rich`，信息更多。
- **`TRUTH_HINT` 还是会被偶尔引用**（「既然您提到『睡没睡』」）。它是「别编造」的代价：
  不告诉它这条，它就编日程；告诉了，它偶尔会提到这条规矩本身。两害相权取其轻。
- **两条 system 消息的隐患没根治**。实测发现模型偶尔把第二条 system 完全当用户输入来议论，
  但改成一条 system 之后工具调用在我们这个探针里两版都不成立 —— 这条探针本身不可信
  （真机上工具是好的），所以**没有动布局**，只在文档里记下这个疑点。
- 时钟从 `【此刻】…` 改成白话之后，「对方没提时间就别主动提」这句话也挪进了人设卡里，
  偶尔仍会主动报时间（「现在是 2026 年 10 月 20 日下午」）。不影响可读，没再改。
