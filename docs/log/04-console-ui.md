## 25. 可视化控制台：本地网页 UI（2026-09-26）

用户要的是「可视化 UI 终端，把现有能力整合进去，并且能在界面上看和改日程/闹钟」，
还要求「模块化，以后接新功能方便」。这一节记的是**为什么这么做**和**踩到的坑**。

### 25.1 为什么是「本地网页 + 独立进程」

选型前先把约束摆清楚：

1. **Tk 那条路基本被堵死**：本项目规定一个进程只能有一个 Tk 解释器、而且只能由创建它的
   线程碰（`voice_loop/ui.py` 顶部那段血泪注释）。窗口、字幕已经占着它了；
   要再加一个带表格/日历的窗口，要么挤进同一线程（跟服务绑死），
   要么另起进程（又跟「一个解释器」的约束打架）。
2. **网页能一次满足三个需求**：表格好编辑、能画周视图、日志能实时跟随——而且不用引前端框架。
3. **独立进程 > 嵌进服务**：界面崩了不影响语音服务；改界面代码不用重启服务（服务重启要重载模型，
   几十秒到几分钟）。代价是需要一条跨进程通道（见 25.3）。

结论：`python main.py ui` = 一个只监听 `127.0.0.1` 的 FastAPI 应用 + 一堆静态文件，
**不碰麦克风、不加载任何模型**。用户也确认了「可以装新依赖」，所以用了 fastapi + uvicorn
（requirements.txt 里单列一段，注明不装也只影响控制台）。

### 25.2 ★两个进程改同一批 JSON：先修「静默丢数据」★

动手写界面之前先解决了一个**会静默毁数据**的问题，因为它直接决定「网页能不能安全地改日程」。

原来的存储只有**进程内** `threading.RLock`（`store.py`），而所有写入都是**整表回写**
（读全部 → 改一条 → 写全部）。单进程没问题，**两个进程各持一份快照就会互相覆盖**：

    服务（提醒线程）：load() → 给 A 标 state.fired → save()
    UI（网页）：      load() → 删掉 B            → save()     ← 后写的把前一个盖掉

⚠️ 它**不报错、不崩溃**，就是数据没了。而且 `load()` 靠 mtime 能「看见」别人的改动，
**也救不了它**——「看得见」和「不会互相覆盖」是两件事（这是我这次最先想清楚的一点）。

修法：`store.cross_process_lock(path)`，用一个**单独的 `.lock` 文件**互斥。

* **为什么不锁数据文件本身**：写盘是 `tmp.replace(path)`，**inode 被换掉了**，
  锁在那个被删掉的 inode 上没有意义（新读者看到的是新文件，锁形同虚设）。
* **可重入**：同一线程嵌套调用（`due_now` 里再调 `save`）不能自己把自己锁死 →
  进程内 RLock + 线程内深度计数，只在最外层拿系统锁。
* **拿不到就等 5 秒再抛**：不让一个卡死的进程把服务永久挂住。
* 顺手把变更检测从「只比 mtime」改成 `(mtime_ns, 大小)`：FAT 系时间戳精度只到 2 秒，
  同一毫秒里写两次会被误判成「没变」而拿到旧缓存。

回归测试 `scripts/tests/test_store_lock.py` §3 是**真·两个进程**：各自在锁内故意睡一下把窗口撑开，
没有锁时最后只会剩 1 条（必错），有锁则两条都在。另加 `EventStore.due_now` /
`update_by_id` 整段持锁（它们也是读-改-写）。

### 25.3 控制台 ⇄ 服务的通道：文件信箱

有些事只有**服务进程**能做：念一句（TTS 在它那儿、模型已经加载好了）、切声线、
文字对话（LLM + 工具 + 记忆都在它那儿）。原来唯一的跨进程通道是
`sessions/listen.stop`——**一个文件，只能表达「停」**。

这里补的是 `voice_loop/control.py`：

    sessions/console/inbox/<id>.json   控制台放请求（先写 .tmp 再 replace）
    sessions/console/busy/<id>.json    服务**改名**过来 = 认领（改名是原子的）
    sessions/console/done/<id>.json    服务写回执，控制台轮询它

**为什么用文件而不是 socket/命名管道**：服务侧不用开线程、不用事件循环，主循环每轮顺手看一眼
（跟 stop 文件同一个位置）；崩了不会留半死不活的连接；一份请求就是一份文件，
出问题直接进去看 json，不需要猜。命令表就五个：`ping / say / ask / character / toast`。

两条**必须**有的规矩（都有测试盯着）：

* **太旧的请求不执行**：服务刚启动时绝不补念十分钟前那句试听——否则你会听到一句
  莫名其妙的「测试一下」在夜里响起来。超时的请求会回一张「太旧，已忽略」的回执，免得界面干等。
* **崩在半路的请求要判失败**：busy 里的文件超过 60 秒说明服务当时死了，
  下一轮把它记成失败回执（不然控制台会等到天荒地老）。

### 25.4 界面：面板就是插件

加一个标签页只要两个文件，**不用改别人的代码**：

    voice_loop/console/panels/xxx.py     PANEL = Panel(id="xxx", title="…"); register(app, ctx)
    voice_loop/console/static/panels/xxx.js   Console.register("xxx", { render(root, ctx) {...} })
    然后在 panels/__init__.py 的 ALL 里加一行

标签栏由 `/api/panels` 动态生成（所以不用碰 HTML），前端脚本按 id 动态加载。
**一个面板装载失败只跳过它自己**，界面照常能用（`/api/meta` 里能看到是谁坏了）。

六个面板：概览 / 日程·闹钟 / 备忘 / 日志 / 角色·声线 / 文字对话。

两个「不重复造轮子」的刻意选择（这是本次最容易做错的地方）：

* **「加一条日程」必须和语音说的是同一套解析**：直接调 `event_text.extract + to_item`，
  连回复文案都用同一个 `render_added`。自己再写一份解析，早晚会变成
  「网页能懂、语音不懂」。实测：网页里打「下周一早上八点去实验室，提前十分钟」
  → 落地成 `2026-09-28 08:00 去实验室 · 提前10分钟 · course`。
* **备忘的清洗也一样**：但 `skills.py` 会连带 import `vision`（Pillow / OpenCV），
  控制台不该为了剥两个词把图像库拉起来，所以自带了同一份触发词正则，
  **再用测试拿真实 skills 的正则逐句比对**（`test_console.py` §7）——
  两边一旦跑偏，测试会失败，不会静静发展成「网页认识的词和语音不一样」。

### 25.5 这轮目视 + 交互测试抓到的 5 个 bug（都是「测不出来、一看就露」的那种）

自动化测试全绿之后，我还是起了一个真浏览器点了一遍——结果抓到 5 个：

1. **面板路由根本没挂上**：`load_panels` 只 import 了模块，忘了调 `register(app, ctx)`。
   表现是 `/api/events` 返回 **405**（请求掉到静态文件那边去了）。
   ★单测里我甚至断言过「面板清单对」——它确实是对的，因为元数据注册了，路由没挂★。
2. **`current is not defined`**：`hashchange` 监听器被我写在闭包**外面**，
   碰不到 `current` / `meta`。顺带发现「手打 `#logs` 不切标签、浏览器前进后退无效」这个功能本身就缺。
3. **少一个右括号**（`voices.js` 整个面板加载失败）：表现是「这个面板没有前端脚本」。
   后来学乖了——**在浏览器里对每个前端脚本 `new Function(text)` 编译一遍**，
   一次就能把六个脚本全查出来（Python 侧没法替你验 JS）。
4. **DOM 节点被拼进字符串**：`"…" + h("span", …)` → 界面上显示 `[object HTMLSpanElement]`。
5. **编辑表单缺「钟点」字段**：重复事件（每周三 9 点）只存 `time` 不存 `start`，
   表单里只有一个 datetime-local，所以**看得见空、改不了钟点**。

顺带修的两个体验问题：`Invalid Date`（概览少返 `started_at`）、
以及**服务没在跑时点「试听」要白等 25 秒**——现在先查进程状态，
立刻回「服务没在跑（pid 文件里是旧进程 12345）——先点右上角「启动服务」」。

★教训★：**自动化测试通过 ≠ 界面能用**。前端那一层（脚本语法、DOM 拼装、
字段是否齐、点了以后到底发生什么）只能靠真点一遍。所以 `sessions/uicheck_setup.py`
这套「隔离演示数据 + 真浏览器走一遍」的做法留下来了：
`python sessions/uicheck_setup.py` → `python main.py --config sessions/uicheck/config.toml ui --port 8766`
（把 `project_root` 指到演示目录，**一条真实日程都不会被动到**）。

### 25.6 已知边界（写清楚，免得以后误以为它能干更多）

* **没有鉴权**：它是本机工具。默认只听 `127.0.0.1`；`--host 0.0.0.0` 会让同局域网的人
  也能改你的日程（README 第 4 节已标明风险）。
* **「点一下试听」有最多 5 秒延迟**：服务主循环每轮抓一次命令（为了不被 `listen_timeout`
  拖住，服务里那个等待上限就是 5 秒），所以命令最多等一轮。
* **控制台不写日志文件**：服务的 `sessions/listen.log` 是服务**独占写**的（stdout 重定向），
  控制台只读。两个进程交错写同一个日志会乱成一团，这条边界不能破。
* **对话历史只在控制台内存里**：刷新就没了。真正的对话记忆在服务的 `llm` 里
  （`history_turns` 控制），网页里「清屏」只清显示。

## 27. 修「UI 上启停服务异常」（2026-09-26，用户报）

用户就一句：「ui 端启动和停止服务异常」。查下来是**两个真 bug 叠在一起**，
而且都是「点一下就看到不对」的类型。

### 27.1 根因一：把「日志里恢复出来的旧 pid」当成了状态

```
sessions/listen.pid  不存在（服务早就退了）
sessions/listen.log  里最后一条是 `服务已启动 PID=40156`（13 小时前）
```

旧 `status()` 是这么写的：

```python
pid = read_pid(settings)        # ← pid 文件没有就**从日志恢复**，捞出 40156
pid_stale = bool(pid) and not alive   # ← 于是「残留」= True
```

于是界面报「服务没在跑（pid 文件里是旧进程 40156）」——可它**根本没有 pid 文件**。
更坑的是启动被这条挡住：

    点「启动服务」→ 「pid 文件里是旧进程——先点「停止」清理一下」
    点「停止服务」→ main.py stop → 「进程 40156 已经不在了，已清理 pid 文件」
    再点「启动服务」→ 这回才能起

用户看到的就是「启停都是坏的」。

★修法★：把三件事分清（`ServiceStatus` 的注释里写死了）：

    running       进程真的还在（pid 文件，或从日志恢复的那个 pid，**验过**）
    pid          **正在跑的那个**；没在跑就是 None（不再拿死 pid 骗人）
    pid_stale    pid 文件存在但里面的进程没了（= 需要清理的残留）

日志里那个旧 pid 只能当历史；`pid_source` 告诉界面 PID 是从哪来的（pid 文件 / 日志恢复）。

### 27.2 根因二：启停**从不验证**结果

旧实现：`spawn()` 成功后直接回「已发出启动命令（pythonw PID xxx）」= **当成成功了**。
可服务可能压根没起来（缺模型、设备被占、单实例守卫拦下…），界面却报「已启动」；
停止也一样，只回 `main.py stop` 的最后一行，服务真死没死不知道。

★修法★：

* 启动：先清残留（调 `main.py stop`，它就干这个的）→ `spawn` → **轮询等到真的在跑**
  （最多 25 秒）→ 成功才说成功；失败就把**日志尾行**一起带出来
  （「启动命令发出去了（pythonw 进程 x），但 25 秒内没看到服务起来。日志最后一行：缺模型…」）。
* 停止：跑完 `main.py stop` 再等「没在跑且没残留」才算成；命令返回了但服务还在 →判失败。
这一层测试用的是**假 spawn / 假 subprocess**（`scripts/tests/test_service_ctl.py`），
所以单测永远不会真的起服务。

### 27.3 真机验证（单测证明不了这些）

`sessions/probe_service_lifecycle.py` 走**UI 按钮用的同一条代码路径**真起真停：

    ① start_service()  → ok=True，0.7 秒返回，消息「服务已启动（PID 28832，来自 pid 文件）」
    ② 再点一次启动    → 被拒：「服务已经在运行（PID 28832）」
    ③ 等 8 秒看日志    → 长了 1671B，尾部是「[待唤醒] 请说「凯尔希」或「阿米娅」…」
    ④ stop_service()  → ok=True，17.7 秒，消息「服务已停止（√ 唤醒服务已停止）」
    ⑤ 再点一次停止    → 「服务没有在运行（也没有残留文件）」（不是报错）

★停止要 ~18 秒★（服务每 ≤5 秒看一下停止文件，还要释放模型/设备），界面必须顶得住这个等待，
所以按钮会先置灰并提示「正在停止服务…」。

### 27.4 顺手修掉一个偶发测试变红

全量跑的时候 `test_route` 红了一次（单独重跑又绿）。真因不是这次改动：
那个用例直接调 `loop.respond("看看桌面上有什么")` 走**真实截图**，采图当场失败时
拿到的是 `vision_error` 而不是 `vision` → 断言 `called == ["vision"]` 就挂了。
改用注入假技能结果（`SkillResult(action="vision", data={...})`），只验**路由**、
不碰摄像头/屏幕；连跑三次稳定绿。

### 27.5 验收

* `scripts/tests/test_service_ctl.py`（新，纯离线）：没 pid 文件就是「没在跑」、有残留算残留、
  启动先自动清理、已在跑就拒、起了没起来要报失败并带日志尾行、停止要验证、
  命令/输出路径检查（pythonw / listen -B / stop）
* `sessions/probe_service_lifecycle.py`：真机四点五次检查全过
* 全套 25 个离线测试 EXIT=0（+ 单独把 `test_route` 连跑三次）

## 28. 控制台的两件事：终端里退不出、聊天不能选角色（2026-09-26 用户报）

### 28.1 ★终端里 Ctrl+C 退不出，只能关网页★ = SSE 把优雅退出拖住了

用户就一句「控制台无法在终端退出，而是只能关闭网页后才退出」。先**复现**（写了个探针）：

    python sessions\probe_console_exit.py --wait 20
    → 挂一条 SSE（模拟网页开着）→ 发 CTRL_BREAK → ★等了 20 秒还没退出★

根因不在 SSE 本身，而在 **uvicorn 的关闭顺序**：

    ① 停止收新连接 → ② **等活跃连接自己结束** → ③ 跑 lifespan shutdown（on_shutdown）

SSE 是「永不结束的响应」，② 会一直等；而我把 `bus.close()`（叫醒订阅者）放在 ③ 的
`on_shutdown` 里，**根本轮不到它执行**——所以只要网页还开着，进程就永远退不出；
关掉网页 → 连接断开 → ② 满足了 → 才退。

★修法分两层★（都在 `console/app.py` + `console/bus.py`）：

1. **接管 `uvicorn.Server.shutdown()`**（子类 `ConsoleServer`）：在 ① 之前就
   `bus.close()`，让 SSE 生成器干净收尾（`_dead` 置位 + 往每个订阅者队列塞一条 `bye`）。
   单靠 ② 里的 `timeout_graceful_shutdown=3.0` 也算兵底——但那会变成「被强关」并打一行
   `Cancel 1 running task(s)`，体验差且日志难看。
2. 订阅者**不再无限 `await q.get()`**：改成 0.5 秒一轮的 `wait_for` 超时轮询，
   顺便看一眼是不是要收摊了（就算 bye 没送到也能自己退）。

顺手加的体验：终端里提示「网页开着的时候，在终端里按 Ctrl+C 也能退出」+ 退出后打一行
「控制台已退出（语音服务不受影响）」；网页侧收到 `bye` 会主动断开 SSE 并提示「控制台已在
终端退出」——否则 EventSource 会徒劳地一直重连。

实测（`scripts/tests/test_console_exit.py`，含对照组）：

    挂着 SSE：★0.3 秒退出★（修前：20 秒都退不出）
    没有 SSE：同样几秒内退出（别把普通情况弄坏）

### 28.2 文字聊天现在能选角色

需求：「文字聊天也应该能选择角色」。做法上有一个刻意的选择：

★角色是跟这条消息**一起**发过去的（`ask` / `say` 命令多一个 `character` 参数，
服务侧在同一条命令里先切再干活），而不是「控制台先切角色、再发问题」★。
分两次的话，中间那一刻可能被语音唤醒或另一个页面换走 —— 就会出现
「界面选的是阿米娅、回答却是凯尔希」这种说不清的事故。放在一条命令里只有一个事实。

细节：

* `control.execute` 里加 `switch_if_asked()`：没给 `character` 就**完全不碰角色**
  （保持「服务当前是谁就是谁」），给了就先切；角色不存在 → 明确失败，
  不默默用别人回答。
* 聊天面板多一个下拉框（「跟随服务当前角色」+ 每个角色），选项里会标出
  「· 现在是她」（来自 ping），选择记在 localStorage 里刷新不丢。
* 回答下面显示**是谁答的**（回执里带 `character_name`）。
* `say`（只念不答）也支持选角色，用同样一条路径。

### 28.3 验收

## 51. 控制台里建角色：一份 SPEC 生成表单 + 导入文件（2026-10-01）

用户要求：「为 ui 添加按格式填写人物资料卡的功能，同时支持选择文件导入」。

### 51.1 为什么是「一份规范」，而不是「前端写死一堆输入框」

人格文件的解析是**白名单式**的（`Character.from_dict`）—— 字段名写错、或者写到
不认识的位置，**不会报错，只会被静默忽略**。于是最典型的用户困惑是
「我明明写了风格，她却不这么说话」。所以这一版的关键取舍是：

> **字段规范只写一份**（`console/persona_card.py` 的 `SPEC`），
> 后端校验、前端表单、导出的模板都用它 —— 前端不写死任何一栏。

副作用是好的：以后加字段只改 `SPEC`（表单自动多一栏、校验自动生效），
而且「不认识的字段」会在提交时报出来（而不是让人以为写进去了）。

### 51.2 它只动两个文件，而且每一步都能回滚

| 步骤 | 规矩 |
| --- | --- |
| 写哪 | `data/personas/<id>.json` + `data/characters.json` **追加一行**（只有索引里有的角色才会被唤醒） |
| 什么时候写 | 接口默认 `dry_run`；前端「预览」只报告，点「创建」才落盘 |
| 写坏了怎么办 | 改前 `.bak`；写完**读回来 `json.loads` 校验**；原子写（先 `.tmp` 再 replace） |
| 重名 | 已有同名 id 必须显式 `overwrite`（前端勾「覆盖已存在」），否则 400 + 人话 |
| 别动别人 | 索引里已有的行原样保留、不重排；别的人格文件一个字节不碰（自测有断言） |
| id 安全 | `^[a-z0-9][a-z0-9_-]{0,31}$` —— ★它是拼路径用的★，不是洁癖（`../evil` 直接拒） |

### 51.3 导入：认两种文件，都是项目自己的格式

- **`.json`**：一张资料卡（就是本面板导出的那份）。整份是数组或 `characters.json` 那种索引时，
  取**第一个**并在界面上说明（不静默猜）；没写 `id` 就按文件名推、也说明。
  编码先按 UTF-8（含 BOM）解，失败再试 GBK —— 记事本存过的老文件很常见。
- **`.txt`**：素材清单（名字一行 + 正文一行）→ **只填「示例台词」那一栏**，
  解析直接复用 `voice_loop.manifest`（和 `import_lines.py` 同一套，不另写一份）。
  界面上明确写「只填了这一栏，其余请自己补」—— 不假装全自动。

导入**不落盘**：读出来填进表单，人看一眼再点「创建」（两步走，和克隆面板一个道理）。

### 51.4 顺手修的测试债

`test_console.py` 里的面板清单/数量是写死的（`["overview", …, "chat"]`、`6`）——
加面板就得跟着改。这次一并更新成 7 个（含 `persona`），并在静态文件清单里加上
`/panels/persona.js`（那个循环本来就是为「新面板的脚本能不能取到」写的）。

### 51.5 测了什么 / 没测什么

- 新增 `scripts/tests/test_persona_card.py`（7 节）：SPEC 自洽（无重名 key、kind 合法、
  模板覆盖所有栏目且自己能过校验）、校验（坏 id / 空名字 / json 写错 / 温度越界 /
  backend 越界 / 「不认识字段」提醒）、预览（走真解析器读回来）、
  落盘（写两个文件 + `.bak` + 重名挡住 + 覆盖才改 + 索引不重排 + 别的人格文件字节不变）、
  导入（json / 数组 / 索引 / txt / 坏 json / 空文件）、接口（spec/preview/create/import/export/404），
  以及第 [7] 节那道**闸门**：跑完比对真实 `data/characters.json`、`kaltsit.json`、`baize.json`

## 54. 控制台「角色」一栏：资料卡与声线合并，★能改已有角色★（2026-10-01）

用户原话：「把角色资料卡和角色/声线做到一起，合并为『角色』栏，没有必要分开，
加入在 ui 端修改角色资料的功能，而不只是覆盖，把『新增』区域放到角色页底下。」

### 54.1 合并：两个标签页 → 一个

「改资料卡」和「换声线」本来就是同一件事的两半：建完角色顺手就要试听，听着不对就要回去改资料。
分成两个标签页只是让人先想「这件事该去哪一页」。

- 面板 `persona` 改名「**角色**」（order 45），`panels/__init__.py` 的 `ALL` 里去掉 `voices`；
- `panels/voices.py` 降级成**路由模块**（没有 `PANEL`，只留 `register(app, ctx)`），
  由 `persona.py` 一并挂上 —— ★**路由路径一个都没改**（仍是 `/api/voices/*`）★：
  「声线」是功能名，跟标签页怎么分无关，所以测试、脚本、README 里的引用都不用跟着动。
- 万一有人把 `"voices"` 又加回 `ALL`：`load_panels` 会报「PANEL 必须是一个 Panel」，
  不会静默双重注册（把一个坏法变成一条响亮的日志）。
- 前端 `static/panels/voices.js` 删掉、`persona.js` 重写成一页；
  `test_console.py` 里的面板清单 / 静态文件清单 / `len(panels)` 跟着改，
  并且加了一条「`/panels/voices.js` 必须 404」—— 留着旧脚本只会让人以为还分两页。

页面顺序就是用户要的：① 试听 ② 角色卡片（切过去 / 试听 / 编辑 / 下载 JSON / 克隆）
③ 全局声线配置（只读）④ ★**新建 / 编辑表单**（最底下）★。

### 54.2 ★「改」不是「覆盖」★（本节的重点）

在这之前，想在 ui 里改一个已有角色，唯一的办法是把整张表重填一遍、勾「覆盖已存在」——
而表单只认识 `SPEC` 里那 24 栏，人格文件里别的键（`enabled` / `default` / `voice_dir` /
`world` / 将来新加的字段）会被**静默删掉**（`Character.from_dict` 是白名单解析，不报错）。
这正是「我就改了个称呼，怎么喊不醒了」的成因。

现在分成两条路：

| 动作 | 函数 | 语义 |
| --- | --- | --- |
| 新建 | `persona_card.create()` | 写 `personas/<id>.json` + 索引追加一行；id 已存在就**拒绝**并指路去编辑 |
| 修改 | `persona_card.update()` | 填成她现在的样子、id 锁住，**只动表单那几栏**，索引与别的文件不碰 |

`merge_into()` 是两者共用的一步（`create` 的 `overwrite` 也走它）：

- 表单里有值的键写进去；表单里**清空**了的键真的删掉（那是用户的意图）；
- 别的键（quiet 键 + 不认识的键）**原样保留**；
- 写完 `.bak` + 当场 `json.loads` 校验；报告里说清**改了哪几栏 / 清掉了哪几栏**。

★两个实测换来的坑（都是「报告刷出一大片假改动」）★：

1. **比较之前要过一遍真解析器**。`from_dict` 有默认值（`user_title` 缺省是「你」），
   拿原始 JSON 直接跟表单比 → 每个角色都会报「改了 user_title」，还会把那个默认值写进文件。
   `_normalized(raw) = preview(None, raw)` 之后就干净了（test_persona_card 里专门钉了这条）。
2. **表单里空着的栏不算改动**。新角色表单一交，`ack` / `temperature` / `knowledge` 全是空的，
   要是把它们都当「改动」，报告就没法看了（现在只报真的变了的）。

还有两条守卫写在 `update()` 里：**索引里没有这个 id 就报错**（编辑不会偷偷建一个新角色，
错误信息直接指路「要建新的就用创建」）、**人格文件读不动就报错**（先去修它，别拿表单去盖）。

### 54.3 前端：「新增」挪到最底下 + 卡片的「编辑资料卡」

- 表单卡片移到页面最底下（角色列表之后），标题会跟着模式变（「新建角色」↔「编辑角色资料：正在改 X」）；
- 编辑模式：**id 栏锁住**（它是文件名，改了就成另一个角色）、主按钮变「保存修改」、
  多一个「取消编辑（改为新建）」；下面那行小字会列出「这些键不在这里改，但会原样保住：enabled、voice_dir、world」
  —— 让人看得见「不会丢什么」，而不只是听我说；
- 角色卡片上加「**★编辑资料卡★**」；正在编辑的那个卡片标题标「★正在编辑★」、按钮置灰；

- **导入**：正在编辑 A 时导入一个 id 是 B 的文件 → 自动切回「新建」模式并说明

### 54.5 用户反馈「并列的当前角色看不到了」→ 真的是 bug，但是**我修的 bug 之外的那个**

上线当天就收到：**角色列表一片空白**。查下去发现是两种失败叠在一起，而且**都不出声音**：

1. **控制台进程是旧的**。他那个页面是在
   **改动之前**启动的控制台进程上打开的（同一个坑的另一面：他随后 `main.py ui` 直接端口占用退 1）——
   旧进程里没有 `/api/voices` 这条路由 → 请求 404。
2. **而我的前端把这件事咽了**：只在那一刻弹了个 4 秒就消失的 toast，角色列表就永远空着，
   **不会重试**；他重启了控制台也没用，因为页面上的那段 JS 已经把「空」画完了。

★根本原因值得记下来★★：这个控制台的**静态脚本是每次请求从磁盘现取的，而路由是进程启动时装载的**。
只改代码不重启，就会出现「页面是新的、后端是旧的」——而它的表现是**一个空页**，不是一条报错。

修了两道（都是通用的，不止这个面板）：

| 守卫 | 做法 |
| --- | --- |
| 面板读不到自己的接口 | 不弹 toast 了：在面板里出一张**可见的错误卡片**（错误原文 + 「Not Found」时直接说清是进程旧了、怎么重启 + 一个「重试」按钮），并且**先自动重试一次**（刚起来的服务常见）；已经有好数据时就只弹提示、不把列表擦掉 |
| 半新半旧的进程 | `app.panel_stamp()` = `panels/*.py` + `static/panels/*.js` + `registry.py` 的内容哈希；`/api/meta` 同时给「启动时」与「现在」两份，`app.js` 不一致就弹一条 30 秒的提醒叫你去重启 |

另外补了两件小事：列表加载中显示「正在读角色与声线…」（真数据 34 KB、要把每个角色的素材目录都体检一遍，
不是瞬时的），试听卡片上多一个「重新读一遍」。

验法（都是真代码真进程，没用 mock）：

- 新进程：两个指纹相等 ✓；插一个临时面板文件（不在 `ALL` 里）→ 两个指纹立刻不等，**页面当场弹出重启提醒** ✓；
  删掉后又相等、提醒消失 ✓。自测里也钉了（换 `PANELS_DIR` 指纹就变）。
- 面板错误态：用 Playwright 把 `/api/voices` 拦成 404 → 弹出的是「✗ Not Found」+ 解释 + 「重试」按钮
  （自动重试一次之后才报）；放行后再点「重试」，列表**当场回来**、按钮消失 ✓。


### 54.6 紧接着的两件：★点卡片就能改★ + 卡片要「并列」

用户接着说：「我是希望角色页里现有资料卡**并列**，然后我想改哪个**直接点它们的资料卡**编辑。」
（他把我上一条说的「角色卡片」当成了概览页那排小卡 —— 说明角色页里那排卡片要么没排开、要么不够像「能点」。）

1. **整张卡片可点 = 进编辑**。之前得去找那个「★编辑资料卡★」小按钮；现在点卡片上的任何文字都行
   （表单会带出她现在的资料、锁住 id、自动滚下去），**卡片当场标上「★正在编辑★」**
   （用本地缓存重画一遍列表，不重新请求）。排除项很关键：`button / input / select / textarea /
   summary / label / a` 与**整个克隆块**（`[data-clone]`）—— 它们自己的行为优先，不能被「进编辑」抢走。
   另外给了 `tabindex=0` + 回车/空格也能进编辑，手型光标**写两份**（样式表 + inline）：
   浏览器的 CSS 缓存有可能还是旧的，而「能点」这件事不该依赖缓存。
2. **「并列」这件事有个 CSS 陷阱**：grid item 默认 `min-width: auto`，所以卡片里**一条不能折行的长路径**
   （`data/personas/kaltsit/晋升后交谈2.wav`）就能把整条轨道顶宽 —— 窗口不够宽时「并列」直接变成一列。
   修法两条：`.grid > .card { min-width: 0 }` + 长路径那几行加 `.wrap-path { overflow-wrap: anywhere }`。
   （实测 1600px 视口下 4 个角色是 3 列并排；窄窗口才退成一列，那是正常的响应式。）
3. **又一条「有的新有的旧」**：改完 CSS 刷新页面，鼠标还是箭头 —— 浏览器抱着旧的 `style.css`
   不放，而同一页的面板 JS 却是新的（缓存策略不一样）。本地工具不该让人跟缓存猜谜：
   现在静态文件统一带 **`Cache-Control: no-cache`**（★不是不缓存★：浏览器每次仍会带
   `If-None-Match` 来问一句，没变就是 304，几毫秒）。自测里钉了 `style.css` 必须带这个头、
   而 `/api/*` 不许掺进来。

## 56. 控制台做成 exe：原生窗口 + 更新功能（2026-10-08）

用户的话：「**控制台做成 exe 加原生窗口，这个可以先做，同时做好更新功能，以便后续更新**」。

这是第 55 节（可交付化）的直接续集。55 节末尾的诚实清单里有两条现在是「未做」：

> - **内置自动更新**：自托管工具不该偷偷换自己的代码 …… 真要做也应该是「通知 + 一键」，不是静默。
> - **单文件 exe（PyInstaller/Tauri 壳）**：能省掉「装 Python」这一步 …… 是另一个量级的事。

这一节把「exe」这半件做了 —— 但只做**控制台**（理由见 56.9）。

### 56.1 先量，再估：把「工作量」变成数字

动手前先做了一次 spike（真冻一个 exe 出来跑），因为「工作量大不大」这种问题
猜出来的答案没有价值。实测数据（本机 Python 3.13.7 / PyInstaller / Windows）：

| 量 | 结果 | 说明 |
| --- | --- | --- |
| 控制台的第三方依赖闭包 | `fastapi` `starlette` `pydantic(+core)` `anyio` `sniffio` `typing_*` ≈ **14 MB** | ★一个重库都不进来★：不碰 numpy / sherpa / openvino / torch / sounddevice |
| onedir 产物 | **50.4 MB**（4154 个文件） | 启动 **1.6 s** |
| onefile 产物 | **65 MB** | 启动 **6.6 s**（每次双击都要解包，实测） |
| 带 pywebview | **54.1 MB** | 只多 3.7 MB（pythonnet 那一串） |
| 不排除重库时 | **354 MB** | 见 56.4：一放行面板的懒导入，语音栈就跟着进来 |
| 冻好的 exe 自检 | 7 个面板全装上、`/api/meta` `/style.css` `/panels/persona.js` `/api/service` 全 **200** | 见 56.8 |

结论：**控制台是这个项目里唯一「冻了真划算」的部分**（它本来就不加载模型、不碰音频设备）。

### 56.2 两个「根」必须分开：`voice_loop/paths.py`（这一节的重点）

冻结之后 `__file__` 指向 PyInstaller 的解包临时目录（`C:\...\Temp\_MEIxxxx`，
**每次启动都换名字**）。而仓库里有 **15 处**「拿 `__file__` 往上推根」：

```
voice_loop/settings.py:11      PROJECT_ROOT = parents[1]        ← config.toml、data/、models/ 全靠它
voice_loop/__init__.py:19      parents[1] / "VERSION"
voice_loop/setup_flow.py:40    ROOT = parents[1]                ← 备份/升级/体检
voice_loop/service_ctl.py:183   parents[1] / "main.py"           ← 起服务
voice_loop/console/app.py:28   static/ panels/（这两个其实是对的，见下）
main.py:265                    [pythonw, __file__]              ← 后台服务
```

留着它们，exe 的现象会是**看起来毫不相干的三件事**：说找不到 `config.toml`、数据写到临时目录、
点「启动服务」起来的是 exe 自己。所以新增 `voice_loop/paths.py` 把「路径从哪来」收成一份：

| 函数 | 含义 | 冻结时 | 源码运行时 |
| --- | --- | --- | --- |
| `app_root()` | **用户的东西**在哪（config.toml / data/ / models/ / sessions/） | exe 附近能找到的项目 → exe 目录 | 源码根 |
| `resource_root()` | **随程序走的东西**在哪（static/ panels/ VERSION） | `sys._MEIPASS` | 源码根 |
| `find_python()` | **跑服务的解释器** | `.venv` → `LOCAL_AI_PYTHON` → PATH | 同上 + `sys.executable` |

三个设计决定，都是被具体问题逼出来的：

1. **`app_root()` 会从 exe 往上找 `config.toml` + `main.py`**（`find_project_root`）：
   onedir 的常见摆法是 `<项目>/console/local-assistant-console.exe`，exe 自己那一层没有配置。
   ★两个文件都在才算数★：只看一个会把用户的下载目录误判成项目。
2. **`service_ctl` 里 `settings.root` 与「代码根」是两回事**：`settings.root` 是**数据根**
   （配置里 `[app] project_root` 可以指到别处，沙盒就是这么干的），而 `main.py` 在**安装根**。
   改错这一步的直接后果：`test_service_ctl` 里那批「起服务用的是 pythonw + 绝对路径 main.py」
   立刻失败 —— **自测当住了这个设计错误**（我自己第一版就是改错的）。
3. **`service_ctl.python_exe()` 不再用 `sys.executable`**：冻结时它是 exe 自己，
   拿它去跑 `main.py listen` 等于让 exe 再启动一遍自己。找不到真 Python 时
   `start_service` 会直接说「控制台是 exe，但找不到能跑语音服务的 Python ……」，
   而不是 spawn 一下然后报「启动失败」。

**防回退**：`scripts/tests/test_paths.py` 用 **AST**（不是 grep）扫上表里那几个文件，
不允许再出现 `parents[N]` —— 第一版用文本搜，结果把我自己 docstring 里
「别退回 `parents[1]`」这句说明也算成违规，所以改成看语法树。

### 56.3 原生窗口：为什么是「三级后端」而不是只做 pywebview

| 后端 | 是什么 | 依赖 |
| --- | --- | --- |
| `pywebview` | 真窗口（Edge WebView2 内核，无地址栏无标签栏） | `pip install pywebview`（Windows 上带 pythonnet） |
| `edge` | Edge 的 `--app=<url>` 模式：看起来就是个应用窗口 | 机器上有 Edge（Win10/11 都有） |
| `browser` | 老行为：系统浏览器开一个标签页 | 什么都没有 |

`choose("auto")` 按上表挑第一个**确实能用**的，`open_window` 起不来时 `serve()` 退回浏览器 ——
「打不开窗口」不该变成「界面打不开」。三条实测结论：

1. **pywebview 要求主线程**：所以窗口模式下结构是「uvicorn 在后台线程 + 窗口占主线程」
   （正好与浏览器模式相反）。窗口关掉 → `server.should_exit = True` → SSE 被 `bus.close()`
   叫醒、干净退出（`ConsoleServer` 那层是第 55 节之前就有的，这次只是把它从 `serve()` 里提出来共用）。
2. **`edge --app` 必须带独立的 `--user-data-dir`**：不加的话 Edge 会把窗口交给
   **已经在运行的那个 Edge 进程**，我们启动的进程立刻退出 —— 于是「关了窗口 = 结束控制台」
   这条就断了（服务还在后台跑，用户以为关了）。实测：加了独立 profile 后进程一直活着（探针验过）。
3. **关窗口 = 退出控制台**，语音服务不受影响（它有自己的启停）。

### 56.4 `console_exe.py` + `make_console_exe.py`：四类必须记住的坑

打包脚本的存在理由就是把下面四条钉死（README 里写一行 PyInstaller 命令，忘一条就是一个
「能跑但残废」的 exe）：

1. ★**面板是「按文件路径动态加载」的**★ → PyInstaller 静态分析看不到面板内部的懒导入。
   第一次冻结时 `schedule` 与 `persona` **静悄悄装不上**（报的是
   `cannot import name 'event_text' from 'voice_loop'`）。修法不是手工列清单，而是
   **用 AST 把 `console/panels/*.py` 与 `console/*.py` 里的 `from ... import ...` 全扫出来**
   当 hidden-import（本次自动扫出 19 个，含 `event_text` / `persona_card` / `panels.voices` / `clone`）。
2. ★**一放行就 354 MB**★：面板经 `clone` 摸到语音栈。控制台**永远不执行**它们
   （它只读 json/toml、往信箱投命令、发静态文件），所以按清单 `--exclude-module`
   显式排除 numpy/scipy/cv2/sounddevice/sherpa_onnx/onnxruntime/openvino/torch/transformers…
   → 354 MB 回到 50 MB，启动也快一截。
3. **static / panels / VERSION 不在 import 图里**，得 `--add-data` 带进去；
   ★panels 必须以**数据文件**躺在原相对位置★（它们是被路径加载的）—— 这是「面板热插拔」
   这个设计在 exe 里的代价，值得付。
4. **`--windowed` 的 exe 里 `sys.stdout` 是 None**：`console_exe.py` 的第一件事就是把
   stdout/stderr 接进 `sessions/console-exe.log`（这正是 `main.py` 里
   `ensure_std_streams()` 早见过的坑）。另外：**双击时没有参数**，所以 exe 还要自己找项目根
   （第 56.2 条）、清理上次更新留下的 `*.old`、以及**端口上已经有控制台时直接把它打开**
   （双击两次是最常见的动作，那时用户要的是界面，不是一句「端口被占」）。

默认 **onedir**：onefile 每次启动要解包 65 MB（实测 6.6 s vs 1.6 s）。
`--onefile` 仍然提供（有人就是要一个文件），`--check` 只打印计划与命令，便于先看再打。

### 56.5 更新：两条路，五个安全边界

`voice_loop/update.py`（★只依赖标准库★，网络可注入 → 自测全程离线）：

- **git 检出**：沿用第 55 节的 `setup_flow.run_upgrade`（备份 → `git pull --ff-only` → 依赖 → 自检）。
- **压缩包 / exe 安装**：读 GitHub Release 的 `latest.json`（走 `releases/latest/download/`，
  不用 API、**没有限流**）→ 备份 → 下载 zip → **校验 sha256** → 合并 → 依赖 → 报告。

五个边界，每一个都是「升级会毁数据」的具体形态：

1. **绝不覆盖用户的东西**：`data/`、`models/`、`sessions/`、`.venv/`、`config.toml` 整块跳过
   （自测里**故意往发布包里塞了 `data/memos.json` 与 `config.toml`**，验证它们一个字节都没被覆盖）。
2. **校验不过就不动**：sha256 不对 → 停手，★连一个文件都不写★（测试同时验「main.py 没被动」）。
3. **拒绝可疑路径**：成员名带 `../` 的包直接拒（zip-slip，不然解压能写到项目外面）。
4. **上游删掉的文件只报告、不删除**：自动删用户目录里的文件太危险（他可能自己加过东西）。
5. **幂等**：同一个包再合一次，报告必须是「新增 0 · 更新 0」（否则每次更新看起来都像动了几百个文件）。

另外两件顺手做对的事：

- **清单里 url 为空时自己拼**（发布时没配 GitHub remote 也不会变成死路）；
- **版本比较按数字**（`1.10 > 1.9`；`1.1.0+unknown == 1.1.0` —— 字符串比会错）。

### 56.6 更新 exe 自己：Windows 允许改名，不允许覆盖

运行中的 exe **不能被覆盖**，但**可以被改名**。所以顺序是「先把自己改名成 `.old`，
再把新内容写到原来的名字上」，不需要批处理、不需要重启管理器那一套；
下次启动时 `cleanup_old_exe()` 顺手清掉。自测用一个假文件验证顺序与清理
（真 exe 的替换要在真机上发布新版本才走一遍，这条是**已知未做真机验证**的一项）。

### 56.7 界面上的「更新」标签（第 7 个面板）

`GET /api/update/check`（只读：当前/远端版本、git 还是 zip、能不能升）、
`POST /api/update/start`（**必须带 `confirm: true`** 才动手，防手滑）、
`GET /api/update/status?since=N`（增量吐进度）、`POST /api/update/restore`（默认只列会覆盖什么）。

★`start` 与 `status` 为什么分开★：下载 + 解压 + `pip install` 可能好几分钟，
同步接口会让浏览器先超时（用户以为坏了，其实正在装）。所以 `start` 立刻返回，
进度由 `Updater` 这个后台线程状态机一点点吐出来 —— 界面上那个日志框就是这么来的。

### 56.8 怎么验的（都是真跑，不是「应该能用」）

| 验的东西 | 怎么验的 | 结果 |
| --- | --- | --- |
| 冻结能不能成 | 真打 onedir + onefile | 50.4 MB / 65 MB |
| 冻出来的控制台能不能用 | `local-assistant-console.exe --selftest`（起服务 + 自己请求 4 个地址） | 7 个面板、4 个 200、**通过** |
| 原生窗口 | 源码模式：pywebview 开窗 → 定时 `destroy()` → 看日志与退出码 | 窗口开、关、`控制台已退出（窗口已关闭）`、退出码 0 |
| 双击 exe 的完整流程 | 起 exe → 用 `FindWindowW` 找窗口 → 发 `WM_CLOSE`（等于点 ×） | 找到窗口、进程**自己退出**、退出码 0 |
| Edge 后端 | 真起 `msedge --app=`（独立 profile） | 进程**一直活着**（`proc.wait()` 的前提成立） |
| 更新核心 | `scripts/tests/test_update.py`（9 节，★不联网★：下载与取清单都是假函数） | 全过 |
| 路径/冻结/解释器 | `scripts/tests/test_paths.py`（8 节，假装的 `sys.frozen` + 真子进程） | 全过 |
| 控制台接口 | `scripts/tests/test_console.py` 第 8 节（把 `update.check` 换成假的，不联网） | 全过 |
| 回归 | 全量 `sessions\run_tests.cmd`（**40 个脚本**） | 全 EXIT=0 |

### 56.9 诚实清单：没做的、以及一个偶发

- **exe 里不含语音服务**：服务要几 GB 模型 + 外部 Ollama + 真实音频设备，冻进去是
  2~4 GB 的怪物，还得给用户装驱动。所以 exe 定位是**控制台/界面**，服务仍由系统 Python 跑；
  exe 点「启动服务」会自己找 `.venv` 或 `LOCAL_AI_PYTHON`，找不到会明说。
- **没有签名**：未签名的 exe 首次运行会被 SmartScreen 拦一下（「更多信息 → 仍要运行」）。
  自托管工具上证书（每年百来美元）不划算，README 里如实说。
- **默认不打包 pywebview**：不打包时窗口走 Edge `--app`（效果接近、零体积代价）。
  想要「连窗口内核一起打包」用 `--with-webview`（实测 54.1 MB，能跑）。
- **exe 自更新没有真机验证过**：逻辑与顺序有测试，但「真的发布一个新版本再让旧 exe 换掉自己」
  要下次发版才有机会走一遍。
- **`test_offline` 偶发失败**：全量跑时撞过一次 `PermissionError: os.replace(... .json.tmp →
  .json)`（临时目录里），单独重跑就过 —— Windows 上文件被占用/被杀软扫的常见竞态，
  与本节改动无关，先记在这里。

### 56.10 分给了多久（事后对照）

当时的估算是「MVP 约 1.5 人日、推荐档 3~4 人日」。实际做下来的分布：
根目录单点化 ~1 h、窗口 ~1 h（含 pywebview 安装与两种后端的真机验证）、
打包脚本 ~1 h（含两次真打）、更新核心 ~1.5 h、面板与命令行 ~1 h、
测试 ~1.5 h（三个脚本 + 全量回归）、文档 ~0.5 h —— 落在推荐档的下沿，
省下来的时间主要是 spike 阶段已经把「体积/启动/依赖闭包」摸清了。

## 59. 控制台改角色卡，把嗓子改没了（2026-11-18）

### 59.1 现象：只改了身份卡上的介绍，声音变了

大肥鱼本来是 `backend = "api"`（DeepSeek 官方 TTS，音色 stella）。
在控制台「角色」标签页点「编辑资料卡」，改了 `title` / `background` / `style`，点保存。
之后她的声音变成了**全局克隆后端**（`[tts] backend = "zipvoice"`）那条参考音频的嗓子，
日志里还刷出「文本相似度 0.914，重采第 2 遍」。

日志里查到的证据链只有一行关键：

```
22:24:52 I voice_loop | [角色] 后端：api → zipvoice（蓝色大肥鱼 指定）
```

`[角色] 后端：a → b` 只在角色有 `backend` 且跟当前不同时打。也就是说：**文件里的 `backend` 没了**。
接着 `_apply_voice` 里 `want_backend = char.backend or self._base_backend`，
空值 → 回落到 `[tts] backend`（克隆）——于是「只改了个介绍」变成了「换了个人说话」。
`git diff` 印证：`"backend": "api"` 这一行被删掉了，同一次保存里 `memory_all` / `voice_ref: ""`
这些空值也一起被收掉了（那是 `Character.to_dict()` 的过滤）。

### 59.2 根因：旧表单遇上新人格文件，空值被当成「用户清空了」

保存链路上有三段，问题出在第一和第三段：

| 段 | 做了什么 | 事故里发生了什么 |
| --- | --- | --- |
| ① 前端 `fill()` | 按 `/api/persona/spec` 的 `options` 画下拉，再把 `/api/persona/get` 的值塞进去 | 那个**控制台进程**是加 API 功能之前启动的，它给的 `backend` 选项是 `["", "piper", "zipvoice"]` —— **没有 `api`** |
| ② 浏览器 | `select.value = "api"` | 值不在选项里时**不报错**，直接把 select 退回第一项，也就是 `""` |
| ③ 服务端 `merge_into()` | 表单里空着的栏 = 用户清空了 → 从文件里删掉 | 于是 `backend` 被删 |

这也解释了「为什么 `tts_voice` 没丢」：它是**新加**的字段，旧进程的字段规范里压根没有，
所以服务端从来没动过它（`KNOWN_KEYS_LIST` 里没有）。**只有「旧进程认识、但选项里没有这个值」的栏会中招**，
`backend` 正好是唯一一个（`engine` 的 `api` 选项也是同一批加的，但它当时是空的，没暴露）。

### 59.3 三处修（都不靠「下次记得重启」）

| 改哪 | 怎么改 | 为什么是这个位置 |
| --- | --- | --- |
| `static/ui.js` + `persona.js` | `UI.keepSelect()`：先把值塞进去，塞不进去就**补一条 `<option>`**（文案「当前值，本版表单不认识」）再选中；表单上方多一行**常驻黄字**说明哪几栏是这样的 | 根因就在「浏览器静默退回第一项」。补一条选项，值就能原样存回去；黄字是提醒「重启控制台后表单才认得它」 |
| `persona_card.merge_into(..., sent=)` / `update(..., sent=)` | 只对**客户端真的送来了**的栏判断「写 / 清」；没送来的栏原样保留。API 那边把 `payload["fields"].keys()` 传进去 | 「没送到」和「用户清空了」是两件事，以前分不出来。现在旧前端 / 别的客户端少送一栏，最多是「这次没改到」，绝不会删 |
| `update()` 告警 + `overview` 显示真话 | 清掉 `backend`/`tts_voice`/`voice`/`voice_ref`/`engine`/`api_*` 时往 `warnings` 里塞一条红字（「这等于换嗓子/换脑子」）；概览页每个角色显示**实际在用的那一路**（`TTS：DeepSeek 官方 · stella`） | 事故里报告只有一行「清掉了 backend」，谁也没看出来。另外概览页原来只显示 `voice`（那是 Piper 退路），`backend=api` 时**看着像在用 piper**，本身就误导 |

### 59.4 怎么验的

| 验的东西 | 怎么验的 | 结果 |
| --- | --- | --- |
| 旧前端不再改嗓子 | `scripts/tests/test_persona_card.py`：`fields` 里去掉 `tts_voice` 再 `update`；以及走 HTTP `/api/persona/update` 少送一栏 | 两处都保住原值（`api` / `stella`） |
| 明确清空仍然生效 | 同上：`backend = ""` 且**送来了** | 真的删掉，并且 `warnings` 里有「backend 被清空」 |
| 下拉值不在选项里 | 浏览器里 `UI.keepSelect(<select 只有 piper/zipvoice>, "api")` | 返回 `api`，选项多一条，`value` 是 `api`（不再是 `""`） |
| 真机 | 重启控制台 → 编辑大肥鱼 → 直接点「保存修改」 | `data/personas/bluefish.json` 里 `backend` / `tts_voice` 都还在；服务热加载日志 `后端：zipvoice → api` |
| 概览页 | 重启后刷新 | `TTS：DeepSeek 官方 · stella`（白泽显示 `piper · zh_CN-huayan-medium`，克隆角色显示 `zipvoice · 参考…`） |

### 59.5 顺带记住的两条

- **控制台是「静态脚本现取、路由在进程里」**：改了面板代码，页面脚本是新的、接口还是旧的。
  这一版起，`fill()` 撞上「值不在选项里」会**自己说出来**，不再靠人去猜。
  （页面顶部那条「面板代码改过了，但这个控制台进程还是旧的」也是同一类保护。）
- **概览页只能显示「她实际在用的」**，不能显示「退路」。`voice` 是 API TTS 失败时的 Piper 兜底，
  不是她在用的声线 —— 显示错了，排查时第一眼就会被带偏。
