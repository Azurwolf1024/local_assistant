## 15. 记忆：会自己整理，也会忘（但重要的事不忘）

> 设计缘由、自清洁规则的推导、开发中抓到的 8 个 bug、以及「全知/不代入」怎么落地的实测，
> 都在工程日志 **第 36 ~ 42 节**。这一节只讲**怎么用**。

参考人脑的**四级记忆**，另外加了一个「会自己整理」的机制 —— 不是一堆永远只增不减的死文件。

| 层 | 人话 | 存在哪 | 会不会忘 |
| --- | --- | --- | --- |
| **L1 原始对话** | 刚说过的话 | `sessions/session-*.jsonl` | 会：滑窗保留最近 **30 天 / 10 个文件**（已提取入库的才敢删） |
| **L2 情节** | 「记得那件事」 | `data/memory/<角色>/episodes.jsonl` | 会：显著性按 **60 天半衰期**衰减；**被问起一次就加回来一点** |
| **L3 事实** | 人设 / 习惯 / 长期偏好 | `data/memory/<角色>/facts.json` | 一般会；**名字、称呼这类 `pinned` 永不衰减** |
| **L4 知识** | 你给它的背景资料 | `data/knowledge/*.md`、`config.toml` 的 `world` | 不会，你放什么它读什么 |

### 用法

平时不用管 —— 每轮对话它会自动挑最相关的几条记忆拼进提示。想自己查：

```powershell
python main.py memory                      # 四层各有多少
python main.py memory --recall "导师"        # 信息检索
python main.py memory --recall "导师" --when 上周   # ★时间 + 信息★：「上周三我们聊过什么」
python main.py memory --remember "记住：周五三点见导师"
python main.py memory --consolidate        # 手动跑一遍自清洁（合并/衰减/提升）
python main.py memory --prune --apply      # 真删已入库的旧原始对话
python main.py memory --who baize --forget <id>
python main.py memsync                     # ★云端同步★：导出 → 提交 → 推送（见下）
```

时间词支持「昨天 / 今天 / 前天 / 上周 / 上周三 / 最近 7 天 / 上个月 / 去年 / 2026-09-20」；
**认不出来它就不按时间筛（不猜）** —— 猜错时间比不筛更坏。

### 云端同步：记忆存到一个**私有**仓库

本地 `data/memory/` 是隐私、被 `.gitignore` 挡着；又要能跨机器用，所以给它单独一个
**你自己确认过是 Private** 的仓库（默认指向 `[memory] sync_remote`）：

```toml
[memory]
sync_on_close = true          # 退出/归档后顺手推一次（失败只记日志，绝不影响退出）
sync_dir = "memory_cloud"     # 仓库的本地克隆（不进主仓库 git）
sync_remote = "https://github.com/<你>/assistant_memories.git"
```

```powershell
python main.py memsync            # 导出 → 提交 → 推送
python main.py memsync --status   # 有没有没推的 / 远端有没有新的 / 各角色多少条
python main.py memsync --pull     # 换机器：把云端的记忆合并回来（不覆盖本地独有的）
python main.py memsync --dry-run  # 只导出到克隆里看一眼，不提交不推
```

仓库里的结构与本地设计一一对应（第 15 节的四级记忆）：

```
memory/<角色>/episodes.jsonl   L2 情景      memory/<角色>/knowledge/   L4 这个角色自己的资料
memory/<角色>/facts.json       L3 事实      manifest.json              上次同步的清单
memory/<角色>/sessions.json    L1 索引      memory/<角色>/context/     L1 活动上下文（段/摘要/段号）
```

| 设计点 | 为什么 |
| --- | --- |
| **滑窗日志（`sessions/*.jsonl`）不上云** | 它是「会被清掉」的工作记忆，云端留一份没用，而且整段对话原文最隐私 |
| **活动上下文（`context/segments/*.jsonl`）★上云★** | 换机器/换设备后「今天聊到哪儿」要接得上。★注意：段里存的就是 user/assistant 原文★（摘要只用来压缩提示词，不替代存档） |
| **`context/dreams/` 不上云** | 它是 episodes/facts 的全量前镜像，只对本机「反悔」有意义 |
| **本地 → 云端是镜像** | 本地删了云端也删，这样「忘掉一条」不会被下一次 pull 又拉回来；删掉的旧值在 git 历史里还能捞 |
| **云端 → 本地是合并** | 按 episode `id` / fact `key` 取新的那份（`updated_at` / `last_seen` 晚的赢），本地独有的照样留着 |
| **推之前先问一次是不是 Public** | 匿名查 GitHub：认出来是公开仓库就**拒推**（记忆里全是个人信息），要硬推得 `--allow-public` |
| **本地一个角色都没有时拒绝同步** | 「镜像」碰上指错目录 / 自测临时目录 = 把云端清空；宁可什么都不做并告诉你 `--pull` |
| **git 一律不交互** | `GIT_TERMINAL_PROMPT=0`：凭据没缓存就当场失败，绝不在退出服务时弹窗把进程挂住 |

### 自清洁（什么时候自己动手）

- **合并**：36 小时内、话题重合的两条情节并成一条；
- **衰减**：60 天半衰期，被检索命中就加回 * 一次；
- **提升**：同一件事在 **≥ 3 个不同日子**出现过 → 升为事实（「他每周三有课」）；
- **裁剪**：情节 > 800 条 / 事实 > 200 条就按权重砍尾。

真正的触发时机是**每次优雅退出**（`close()` 里先归档、再整理）；平时不打扰你。

### 上下文是连续的：不可变段 + 每晚「做梦」

以前的 L1 是「每次开机另起一个 `session-*.jsonl`」：早上喊一次、晚上喊一次就是两段
互不知情的对话，模型能看见的只有 700 字摘要 —— 答不上「我刚才说啥」。
现在**每个角色一条不断生长的上下文**（`data/memory/<角色>/context/`）：

```
segments/seg-000001.jsonl   ← 已封存：★永不改写★（下面解释为什么）
segments/seg-000002.jsonl   ← 打开中：每轮只往后追加
digests/2026-11-19.json     ← 做梦产出：摘要 / 没聊完的事 / 定下来的事
dreams/2026-11-19.json      ← 那次梦改了什么（含 `--undo` 用的前镜像）
state.json                  ← 段号 / 序号 / 上次整理到哪儿 / 缓存记账
```

**为什么必须「封存后一个字节都不动」**：云端的前缀缓存（DeepSeek 的上下文缓存）按
**前缀字节**匹配，命中部分只要 1/10 价。旧的段不动、新内容只往后追加，白天每一轮都能命中；
每轮重写整段历史（以前那样）就永远命不中。提示词的布局就是照这个排的：

```
事实（L3，一天只变一次） → 往日摘要（做梦产出，一天追加一次） → 最近原文（只追加）
```

**压缩 ≠ 删除**：封存的段还在磁盘上（`recall` 照样检索得到），只是不再逐字进提示词，
用 `digests/` 里那几行摘要代替。真正「把话说完就忘」的事不会发生。

#### 做梦（sleep-time compute，参考 Letta / Zep）

白天不该停下来做「这条值不值得记」，纯规则又太笨（分不清随口一说和以后真有用）。
所以把判断挪到**离线**：夜里一个 agent 读完今天的对话，交一份结构化提议，由确定性代码
逐条校验后执行。两种跑法：

| 跑法 | 谁用 | 干什么 |
| --- | --- | --- |
| `rule` | **本地角色默认** | 不调模型：封段 + 规则抽取 + 规则摘要（毫秒级，不花 token） |
| `agent` | 云端角色 | `read_turns` / `query_memory` / `done` 三个工具 → 提议 → 五道校验 → 落盘；失败自动退回 `rule` |

**五道校验**（防「整理」把记忆改坏）：

1. `pinned` 的身份事实（名字、称呼）**不许** `forget` / `supersede`；
2. `promote` 的 `evidence_seq` 必须是**对方说过的**那一轮 —— 工具/网页输出不能当证据（防 poisoned consolidation）；
3. `(key, value)` 已经记过 → 判 NOOP，不重复加；
4. 一次梦最多改 `max_actions` 条；
5. 改之前先存前镜像 `dreams/<date>.json`，`--undo` 能**整批回滚**。

**三个触发 + 关机补一次**（★2026-11-20 改的★：以前「夜里到点必跑」，哪怕当天只说三句话
也要起一次 agent 梦 —— 那是纯烧钱；「空闲 20 分钟自己醒一次」也删了，它和「模型主动」重复
而且不请自来）：

| 触发 | 条件 | 跑法 | 为什么是它 |
| --- | --- | --- | --- |
| ① 深夜 **且** 够长 | `02:00-05:00` 里随机挑一分钟，**并且**没整理的内容 ≥ `night_min_tokens`（80000） | **agent** | 主路径。两个条件同时满足才做：不够长就只记一句「今天没攒够」，一分钱不花 |
| ② 积得太长 | 任意时刻 ≥ `hard_tokens`（240000） | **rule** | 保命。不压就会把上下文顶爆，而规则版毫秒级、不调模型 |
| ③ 模型主动 | 角色调 `mcp__memory__request_dream`（你说「整理一下记忆」） | **agent** | 你说了才做 |
| ④ 关机补一次 | 退出服务时，`compress_on_close = true` | **rule** | 不调模型、不花钱。只为防止「23 点关机、永远赶不上 02:00 窗口」→ 那天的对话永远变不成摘要 |
| — 手动 | `python main.py dream` | 跟角色 | 备用扳机，排查时用 |

**80000 / 240000 这两个数怎么来的**：云端 API 的上下文窗口有 1M，这两个数按窗口的 8% / 24%
取，给长对话留足空间（1 token ≈ 1.3~1.5 个汉字，一轮日常对话约 100~300 token）：
- 80000 token ≈ **连续几天的长聊**（几百轮）—— 攒到这个量才值得让模型读一遍、提炼进 L3；
- 240000 token ≈ **1M 窗口的 24%** —— 到这儿必须压，但只用规则版，不花模型的钱。

换算成"要聊多久才会触发一次"：一天只跟她说三五句（<1000 token）→ **不触发**，一分钱不花；
平时正常用（几千 token）→ 也不触发，内容先按天累积；攒到 80000+ 才有夜里那一次 agent 梦。

```powershell
python main.py dream                       # 手动做一次（本地角色 = 规则版）
python main.py dream --dry-run             # 只算不改：把摘要和提议打出来看一眼
python main.py dream --date 2026-11-19     # 指定哪天
python main.py dream --who baize --force   # 新内容不够也照做
python main.py dream --undo 2026-11-19     # ★反悔★：整批回滚那一次梦
```

控制台「上下文与整理」卡片能看到每个角色几段 / 打开中几轮 / 上次整理 / 今天缓存命中率，
也有一个「现在整理一次」按钮（规则版，不花云端 token）。

```toml
[memory.context]
segment_tokens = 1200        # 一段写满多少 token 封存（太小前缀碎，太大 miss 一次更贵）
digest_days = 3              # 提示词里往前带几天的摘要
tail_tokens = 2000           # 「刚才聊的」原文预算（按整轮砍，不切半句）
local_tail_tokens = 800      # ★本地模型那一档★：窗口小、注意力弱，塞多了更糊涂

[memory.dream]
enabled = true
window = "02:00-05:00"       # 深夜窗口（条件①的一半）
night_min_tokens = 80000     # ★条件①的另一半★：没攒够就跳过（省钱的主要开关）
hard_tokens = 240000         # 条件②：积到这么多就压（规则版，不调模型）
compress_on_close = true     # 条件④：关机补一次规则版（不花钱）
min_turns = 4                # 少于 4 轮不值得压
model = ""                   # 空 = 跟角色引擎；"api:deepseek-chat" = 整理用更强的模型
sync_after = true            # 梦完顺手推云端
```

| 设计点 | 为什么 |
| --- | --- |
| 段封存后不改 | 前缀缓存能命中的唯一办法（省 90% 输入成本） |
| 摘要放在原文**之前** | 一天只追加一次 → 白天后续请求的前缀不动 |
| 本地角色只跑规则版 | 4B 做「选择性判断」会往 L3 灌噪声，还不如不记 |
| 上下文也上云 | 换机器后「今天聊到哪儿」接得上；段是追加文件，镜像过去字节不变 |
| 拉回来按 `uid` 合并 | 两台机器各自追加过同一段时，整段覆盖会丢行 |
| `--undo` 有前镜像 | 整理是模型做的判断，必须给一条「反悔」的路 |

### 换世界观 / 接知识库

把 `.md` / `.txt` / `.json` 丢进 `data/knowledge/` 就行（格式看里面的 `README.md`），
或者临时写在 `config.toml`：

```toml
[memory]
enabled = true
world = "白泽是通晓万物之名的瑞兽，如今住在本地机器里……"   # 临时一段设定
```

以后想接外部知识库（向量库 / 联网检索），实现一个 `search(query)`
返回片段数组的类，传给 `build_knowledge(providers=[...])` 就行（接口在 `voice_loop/memory/knowledge.py`）。

### 多角色：各看各的世界观（知识库也能共享）

知识库（L4）分三层，**摆法决定谁看得到**：

| 放哪里 | 谁能检索到 |
| --- | --- |
| `data/knowledge/某个文件.md`（**顶层**） | **所有角色**（这就是「可以调用相同知识库」） |
| `data/knowledge/<角色id>/任何文件.md` | **只有那个角色** |
| `data/knowledge/_worlds/<世界观>/…` | **挂了这个世界观的角色**（同 IP 共享一套） |

```
data/knowledge/
    _README.md            ← 下划线开头 = 说明文件，不当知识
    通用说明.md            ← 大家都看
    baize/世界观.md        ← 只有白泽看
    kaltsit/补注.md        ← 只有凯尔希看
    _worlds/明日方舟/泰拉.md   ← ★凯尔希 + 阿米娅都看★（一份文件，两人共用）
```

### 同一个 IP 的角色共享世界观（不用拷文件）

人格文件里写一行就挂上了：

```json
{ "id": "kaltsit", "name": "凯尔希", "worlds": ["明日方舟"] }
{ "id": "amiya",   "name": "阿米娅", "worlds": ["明日方舟"] }
```

两个明日方舟的角色共享 `data/knowledge/_worlds/明日方舟/` —— **想改设定只改一处**。
白泽没挂任何世界观，所以它拿不到明日方舟的设定（它有自己的 `baize/`）。

一个角色的知识库是三层叠起来的（以凯尔希为例）：

```
共享（所有人） → 世界观组（挂了的人） → 专属（自己） → 内联 world（人格文件里写的）
```

可挂多个世界观（`["明日方舟", "联动活动"]`）；`knowledge_shared = false` 只关掉**共享那一层**，
世界观组是它自己挂的，照用（否则凯尔希会说「我不是明日方舟的」）。
看 `stats` 就知道每层各有多少段：`{'local': 6, 'local:world:明日方舟': 4, 'local:kaltsit': 2}`。

人格文件里还能再细控（可选）：`knowledge` 显式路径、`world` 内联世界观。

```json
{
  "id": "amiya", "name": "阿米娅",
  "knowledge": ["data/knowledge/amiya/泰拉.md"],
  "knowledge_title": "泰拉大陆",
  "world": "阿米娅是罗德岛的领袖……"
}
```

检查某一名的知识库（`local` = 共享，`local:<角色>` = 它自己的）：

```powershell
python main.py memory --who baize            # knowledge: {'local': 6, 'local:baize': 3}
python main.py memory --who baize --knowledge 白泽
```

★隔离是断在检索层的★：共享库只收**顶层文件**、不收任何角色子目录，
所以凯尔希拿白泽的设定去回答这类事在结构上就不会发生（自测里逐条钉住）。

### 看图也进记忆（按人脑那三层）

| 层 | 存什么 | 会不会过期 |
| --- | --- | --- |
| **感觉输入** | 图片本身（`data/vision/`，环形缓冲 40 张） | 会：新的顶掉旧的 |
| **情节记忆** | 「什么时候、你让我看什么、我当时看到了什么」＋图片**路径** | 会：跟情节的显著性一起衰减 |
| **回忆** | 图还在 → 能再看一眼；图没了 → 只记得「当时看到了什么」 | — |

```powershell
你说：看看我的屏幕上是什么        # 拍/截图 → 交给视觉模型 → 同时记一条「看过屏幕截图」
你说：上次那张截图里写了什么        # 从记忆里把那张找出来再看一眼（重启后也认）
```

两个细节值得知道：

- 图片在记忆里**只存路径**，不存像素 —— 回忆是“重建”，不是“回放”（人脑也是这样）。
- **被记住的图不会被环形缓冲删**（重要的事记得久）；等那条记忆自己淡忘到一定程度，
  图片才跟着一起褪色（不然磁盘会被很久以前的截图填满）。

### 模型自己会去查（MCP 工具）

除了每轮自动带上的记忆摘要，记忆还挂了两个 MCP 工具（见 `config.toml`）：

| 工具 | 干什么 |
| --- | --- |
| `mcp__memory__recall` | 按内容 + 时间检索（「上次」「上周三」这类说法直接传 `when`） |
| `mcp__memory__remember` | 记一条（用户说「记住…」、或提到值得长期留的偏好时） |
| `mcp__memory__request_dream` | 请它在后台整理一遍记忆（「你整理一下」时用；★API 角色才看得到★） |

好处是模型可以从「被动接受几条」变成「自己去翻旧账」：
你说「我们上个月是不是聊过这个」，它会先 recall 再回答，而不是凭印象编。

只露出 2 个工具是有意的：工具一多本地小模型就选不准（实测 8 个是甜点，
加上这两个共 10 个）。`memory_stats` 没露给模型，留给命令行和外部 agent；
`request_dream` 只在云端角色的 `api_tools` 里带 `memory` 预设时才开（本地那档不开）。

### 白泽默认「什么都知道」（★看向旁处，不代入★）

默认助手白泽在人格文件里开着两个权限：

```json
{ "memory_all": true,      // 能查所有人的记忆（查完会说清每条是谁记的）
  "knowledge_all": true }  // 能看全部知识库（所有世界观 + 别人的专属资料）
```

- **`memory_all`**：`python main.py memory --recall "体检报告" --all` 就跨角色查；
  对话里模型自己用 `who="*"`（或「全部角色」）—— ★每条结果都标着属于谁★。
- **`knowledge_all`**：它的知识库里会**额外并入**所有 `_worlds/<世界观>/` 和别人的专属资料 ——
  于是它既能聊明日方舟、也能聊别人的设定；**看得到归看得到，每条片段都带着归属**
  （检索结果里会显示 `[资料·凯尔希 的专属资料]`、`[资料·明日方舟（世界观）]`）。
- ★**不代入**★：开了这两个权限的角色，系统提示里会自动多一段要求 ——
  提到别人时用旁观说法（「据我所知」「在……的设定里」），**不要说成自己的身份、来历或经历**。
  没有这一段，小模型会把资料当成自己（「我来自泰拉」「我是罗德岛的医疗主管」），而且不会报错。

**特意关掉**：`"knowledge_all": false` → 还能跨角色查记忆，但不再看别人的世界观；
`"memory_all": false` → 连跨角色查记忆也关掉（两个都关就是严格只看自己那份）。
不写 `knowledge_all` 时它**跟随 `memory_all`** —— 这就是「默认拥有、除非特意关闭」的写法。

别的角色默认没有这两个权限（`false`），所以凯尔希看不见阿米娅的、也看不见白泽的；
找不到该角色时也一律**不给**权限（不会退回默认角色 —— 白泽恰好开着，一退就是"不小心把权限发出去了"）。
命令行加 `--all` 不需要权限：那是你本人在终端上查，权限拦的是**角色**。
- 每轮自动拼进提示词的那份摘要**不跨角色**（只带当前角色），跨角色只发生在你明着问的时候。

### 多角色：记忆分开，日程共用

- 每个角色一份目录 `data/memory/<角色>/`：**经历、事实、知识互不可见**；
- 唯一共享的是**日程**：记忆只**读** `data/events.json`，写入永远只走技能 —
  两条写路径必然互相覆盖，所以一开始就只留一条。

### 能删吗

能。删文件就等于失忆：删 `episodes.jsonl` 丢经历、删 `facts.json` 连人设也丢
（重开一次会重新种下名字 / 称呼这类身份事实）；旧原始对话怕删错就先
`python main.py memory --prune`（默认只看不删）。
